# v0.1.4-auth-nav-shell Release Notes

Date: 2026-05-11

## Summary

This checkpoint stabilizes the authenticated app shell and account-ledger safety layer. It adds sign-up, cookie-backed Supabase auth, protected route checks, parser API authentication, user-profile bootstrap support, atomic account-ledger database functions, and guide-style verification documentation.

## Added

- Email/password sign-up page.
- Cookie-backed Supabase browser/server clients through `@supabase/ssr`.
- Next.js proxy protection for private routes.
- Server-side authentication check for `/api/aego/parse`.
- User-profile bootstrap migration.
- Atomic ledger transaction and reversal RPC migration.
- Local verification guide for non-coder testing and manual Supabase steps.

## Changed

- Manual account-ledger writes now call Supabase RPC functions so transaction rows and balance updates succeed or fail together.
- The public landing page remains visible to signed-in users while showing authenticated actions.
- Project setup, security, architecture, database, and Supabase docs now explain the current auth and ledger workflow.

## Fixed

- Browser-extension hydration warning noise at the root layout.
- Mixed signed-in navbar and logged-out landing-page calls to action.

## Verification

- `npm run typecheck` passed.
- `npm run build` passed.
- Supabase migrations `0005_user_profile_bootstrap.sql` and `0006_atomic_ledger_functions.sql` were applied.
- Email verification sign-in flow was tested.
- Manual transaction creation and reversal were tested after the atomic ledger migration.
- Signed-in landing-page behavior was tested.

## Known Limitations

- Usage-credit enforcement is still pending.
- Parser results are not yet persisted as `ai_messages`.
- Chat actions are not yet saved as structured database records.
- Some npm audit advisories remain in the Next/PostCSS dependency chain; forced audit fix is not safe because it proposes breaking framework changes.
