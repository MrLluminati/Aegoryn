# AegorynOS Brand Guidelines

This document defines the lightweight brand foundation for the AegorynOS MVP.

The purpose is to keep the product visually consistent while avoiding a full logo/marketing-branding sprint too early.

---

## 1. Brand Positioning

**Product name:** Aegoryn  
**System/App name:** AegorynOS  
**Assistant name:** Aego  
**Tagline:** Guard your records. Command your life.

AegorynOS should feel like a premium private command system for personal records, finances, tasks, projects, and future expert workflows.

The tone should be:

- premium;
- guardian-like;
- calm;
- precise;
- private;
- structured;
- modern;
- trustworthy.

The product must not look playful, childish, noisy, or overly corporate.

---

## 2. Visual Direction

The MVP visual identity should use a dark, command-dashboard style.

Core visual ideas:

- black / near-black surfaces;
- muted parchment text;
- gold accent for important actions and highlights;
- soft rounded cards;
- subtle borders;
- spacious layouts;
- clear hierarchy;
- minimal visual noise.

---

## 3. Color Foundation

Current MVP palette:

| Token | Use | Value |
|---|---|---|
| Aegoryn Black | app background | `#030303` / near black |
| Deep Panel | cards and forms | near-black translucent surfaces |
| Aegoryn Gold | accents, primary CTA, highlights | `#d6b935` style gold |
| Parchment | main text | warm off-white |
| Muted Text | secondary text | white with opacity |
| Border | card and section borders | white/gold with low opacity |

Color usage rules:

1. Gold should be used for emphasis, not for large background areas.
2. Primary action buttons may use gold.
3. Destructive actions should not use gold; use caution styling later.
4. Financial values may use gold when they represent key metrics.
5. Avoid bright saturated colors unless used for charts with a controlled palette.

---

## 4. Typography Direction

The MVP can continue with the current system font stack.

Typography should feel:

- clean;
- technical;
- readable;
- premium;
- not decorative.

Future typography options may be explored later for marketing surfaces, but app usability is more important than decorative branding at this stage.

---

## 5. Logo Direction

The MVP should use a simple temporary mark until the product flow stabilizes.

Acceptable temporary directions:

- wordmark: `AEGORYNOS`;
- assistant name: `Aego`;
- minimal shield / aegis mark;
- stylized letter `A`;
- circular command-system mark.

Full logo-suite creation should wait until the product has:

- working AI parser;
- useful visual analysis;
- private deployment;
- clearer public positioning.

Future logo suite should include:

- primary logo;
- app icon;
- favicon;
- mobile splash icon;
- social profile mark;
- light/dark variants;
- brand guideline PDF.

---

## 6. UI Component Rules

Use consistent patterns across all screens:

- rounded cards;
- subtle borders;
- dark glass-style panels;
- gold eyebrow labels;
- high contrast headings;
- muted explanatory text;
- pill buttons for navigation;
- form fields with dark backgrounds and gold focus states.

Primary screens should share the same page shell:

- top brand label;
- page title;
- short subtitle;
- right-side navigation/action cluster;
- content cards below.

---

## 7. Product Copy Rules

AegorynOS copy should sound like a private command system, not a generic finance app.

Preferred language:

- records;
- command;
- ledger;
- dashboard;
- assistant;
- classify;
- structure;
- source text;
- audit trail;
- guard;
- private;
- verification.

Avoid overusing:

- cute assistant language;
- gamified language;
- casual jokes;
- exaggerated AI claims;
- promises of professional legal/tax outcomes.

---

## 8. Scope Rule

This is a lightweight MVP brand foundation.

Do now:

- preserve consistent UI theme;
- use consistent colors and layout patterns;
- keep the Aegoryn/Aego naming coherent;
- add a simple temporary identity.

Do later:

- final logo suite;
- marketing website design;
- mobile app icon;
- public launch brand assets;
- pitch deck visual system.

---

## 9. Versioning

The initial brand foundation should be treated as a small checkpoint before the AI parser phase.

Recommended tag after implementation and build verification:

```text
v0.1.3-brand-foundation
```

This tag should not replace the account-ledger rollback tag. It should act as a UI/brand consistency checkpoint before `v0.1.5-ai-parser`.
